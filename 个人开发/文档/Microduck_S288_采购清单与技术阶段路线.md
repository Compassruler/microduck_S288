# Microduck-S288：采购清单与技术阶段路线

> 版本：V1.0  
> 整理日期：2026-10-01  
> 项目路线：宇树 S288 + Raspberry Pi 5 开发；后续评估 Radxa ZERO 3W 与自制 STM32 下位机。  
> 第一目标：先完成单舵机、五舵机和单腿验证，再推进整机强化学习行走。

---

## 阅读说明

本文把目前讨论整理成一份可以逐项执行的项目计划。采购状态按已明确的信息填写，**计划购买不等于已经下单**。

- **用户信息**：已有设备、商品截图参数、S288 学生价与限购规则，来自本次讨论，未当作厂家实测数据。
- **资料事实**：舵机协议、器件规格、软件接口等附资料编号，可在文末找到来源。
- **工程建议**：分阶段顺序、测试方法、验收目标和软件组织方式，是本项目的实施建议，不是厂家保证。
- **待确认**：没有可靠规格或尚未实测的项目，不以“肯定够用”“一定兼容”替代验证。

**当前最重要的四个边界：**

1. 一块 3S 电池可以同时供舵机和主控；主控支路需要降压，不需要仅为此增加第二块电池。
2. S288 总线支持 15 个地址，**不等于转接板、PH2.0 接口和所有线束能承受 15 个舵机的总电流**。
3. 已有 Microduck 训练框架和可编辑 CAD 可以复用，但不能把 HD1910 参数、驱动和已训练策略直接当成 S288 版本。
4. 第一版不强制增加 STM32，也不要求使用 ROS；先验证接口和控制，再决定是否集成自制板。

## 1. 项目方案与现有资源

### 1.1 方案基线

| 模块 | 当前方案 | 说明 |
|---|---|---|
| 执行器 | 宇树 S288 | 首批计划 5 个；完整机器人目标 15 个 |
| 开发主控 | Raspberry Pi 5 | 复用已有设备，负责硬件调试和板端推理 |
| 最终上机主控 | Pi 5 或 Radxa ZERO 3W | ZERO 3W 是小型化候选；在最终训练前确定上机布局 |
| 舵机接口 | 宇树单总线串口转 USB 板 | 第一版采用官方适配器，不自研 6 Mbps 物理层 |
| IMU | LSM6DSV16X 成品模块 | 直接接主控 SPI/I²C；不要误买成裸芯片 |
| 开发电池 | 已有格氏 3S 3300mAh 30C | 放在台架上使用，不默认装到机器人身上 |
| 上机电池候选 | 3S 1800mAh 45C | 来自此前商品截图；约 145g，需实测尺寸、重量和电流能力 |
| 机械起点 | Microduck XL330 版 SolidWorks 复刻模型 | 导入 S288 后试配、改型，不直接按原版打印整机 |
| 训练工具链 | microduck_rl / MjLab / MuJoCo Warp / PPO | 在 NVIDIA GPU 电脑上开发训练 |
| 部署形式 | ONNX Runtime + 自己的 S288/IMU 驱动 | 策略频率初始沿用参考项目的 50 Hz，实测周期 |
| 后期集成 | STM32 + IMU + S288 收发 + 配电/降压 | 属于后续版本，不是第一阶段必须采购的硬件 |

参考 Microduck RL 项目采用 50 Hz 策略并导出 ONNX。本文计划保留这条训练与部署链，替换执行器相关部分。[S4](#source-s4)

### 1.3 电池选择记录

以下尺寸、质量、倍率来自用户截图，均需以收到的实物为准。[U2](#source-u2)

| 电池 | 标称能量计算 | 图示尺寸（厚×宽×长） | 图示质量 | 定位 |
|---|---:|---|---:|---|
| 3S 1300mAh 30C | 11.1×1.3 ≈ 14.4Wh | 23×37×73mm | 130g，标有 ±15g | 更短；机身空间紧张时可评估 |
| **3S 1800mAh 45C** | **11.1×1.8 ≈ 20.0Wh** | **25×32×94mm** | **145g，标有 ±15g** | **当前上机优先候选** |
| 3S 2200mAh 45C | 11.1×2.2 ≈ 24.4Wh | 20×36×110mm | 190g，标有 ±15g | 续航需求明确后再考虑 |
| 已有 3S 3300mAh 30C | 11.1×3.3 ≈ 36.6Wh | 21×44×141mm | 248g，标有 ±15g | 桌面开发 |
| 已有 E326S 2550mAh | 实际标称电压、容量口径确认后再算 | 24×61.6×88.6mm | 184g | 放电能力未确认，不定为主方案 |

选择 1800mAh 的理由是商品标称容量、质量与尺寸的折中，不是已经验证它能满足整机全部工况。两款商品的质量公差有重叠，不能把“只重 15g”当成实物保证。

**不预先承诺续航。** 后续通过电池端记录的电压、电流积分得到实际能耗，再确定容量。不同电压的电池比较储能应看 Wh，而不是只看 mAh；倍率标签也不能代替完整供电链路的额定电流。

### 3.2 下单前向宇树确认

可直接发送以下询问：

> 我使用 S288 做 15 关节双足机器人，前期先接 5 个，采用 3S 电池。请确认：
> 1. 这块单总线 USB 转接板从 XT30 到各输出接口的持续电流、峰值电流及峰值允许时间；
> 2. PH2.0 接口与原装线束的持续电流额定值，以及推荐的 15 舵机分组供电接法；
> 3. XT30（2+2）扩展口的准确引脚定义，是否用于本型号舵机扩展；
> 4. 3S 电池满电及再生制动时的供电建议，是否需要额外处理回灌/过压；
> 5. S288 目标位置、力矩、Kp/Kd 的单位、上电零点与超时后的具体动作；
> 6. Python/STM32 官方例程、建议固件版本、后续 10 个的教育科研采购方式。

不要把“支持 15 个设备”当成上面所有问题的统一肯定答案。

## 4. 供电、通信与 IMU 接线

### 4.1 第一版：主控独立供电，先把执行器接通

```text
可靠 USB-C 电源 ───────────────→ Raspberry Pi 5
                                      │
                                      │ USB-A → Type-C 数据线
                                      ▼
3S 电池 → 保险/断电 → XT30 → 宇树 USB 转单总线板
                                      │
                                      │ PH2.0：SIGNAL / VCC / GND
                                      ▼
                                 S288 #0
                                      │
                              验证后逐台增加节点

Raspberry Pi 5 的 GPIO ── SPI 或 I²C ──→ LSM6DSV16X 模块
```

这是逻辑拓扑，不是经过电流额定验证的 15 舵机接线施工图。第一次只接一个，完成验证后再扩展。官方手册给出了 XT30 外部供电、USB 主机与 PH2.0 舵机接法。[U1](#source-u1)

**IMU 不接宇树板。** 直接由 Pi 读取；不采购 Dynamixel 专用 `imu_to_dxl`。后者用于把 IMU 数据挂到 Dynamixel 总线上，不能直接插进 S288 总线。[S7](#source-s7)

### 4.2 同一块电池同时供舵机与 Pi

```text
                         3S 电池
                            │
                       主保险 / 主开关
                            │
                     电源分配节点
                     ┌──────┴───────────┐
                     │                  │
              舵机支路保护/断电     DC-DC 稳压
                     │                  │
              宇树板/额定配电      约 5.1V 主控供电
                     │                  │
                 S288 总线         Raspberry Pi 5
                     ▲                  │
                     └──── USB 通信 ────┘
```

分电发生在转接板之前。**不需要第二块电池，也不需要为了这件事立即设计 PCB。**

Pi 5 官方文档推荐有足够电流能力的供电，并说明 USB 外设电流预算受供电识别影响。因此“降压模块上写 5A”不等于配上任意 Type-C 线就能得到合规、稳定的 5A 供电；USB-C/PD、电缆和散热都需要核对。[S8](#source-s8)

不要把 3S 电池直连 Pi/IMU，也不要未经电源管理设计同时并联两个 5V 电源。舵机回流不应借道细 GPIO 地线；供电地和通信参考地要按拓扑正确连接。

### 4.3 整机配电：看电流，不看地址数量

若实测和额定资料证明官方板及线束满足整机全部工况，可继续使用，不必为了“专业”而增加板子。若不满足，则采用分组供电，例如左腿、右腿、头部各自馈电，通信仍可保持一条主机管理的总线。

多点馈电也需要电气设计：必须明确每条 VCC/GND 的路径，避免细舵机线成为非预期的并联大电流通路；通信分支长度和波形另行验证。**不要把多个独立电源直接并在总线上。**

XT30（2+2）在现有手册只标注为扩展接口；针脚、电平、功能未确认前不使用，不推定其为 CAN、RS485 或第二电池口。[U1](#source-u1)

### 4.4 电压与电池使用边界

S288 产品页给出的输入范围是 **6.4～12.6V**；这不是 J288 的电压范围。标准 3S LiPo 满充 12.6V，属于本项目候选，但满电已靠近 S288 上限，需考虑开关瞬态和再生制动回灌，不能只用万用表测一次静态电压就宣布供电设计完成。[S1](#source-s1)

项目安全要求：

- 使用匹配电池化学体系与串数的平衡充电器，不使用 LiHV 模式超充，不在机器人负载连接状态下随意边充边试。
- 不使用鼓包、破皮、受压或异常发热的电池；充电有人看护，遵守电池/充电器说明，远离可燃物。
- 保险靠近电池，额定值根据最弱导线/连接器及正常峰值确定。
- 每节欠压阈值按电池厂商要求设置；**不能等到 S288 的最低工作电压才保护 3S 电池**。
- 大电池具有很高短路能量。首次查线尽量断电测通断，有条件先用限流电源排查；电池不是实验电源的限流替代品。
- 主控软件关机与舵机紧急断电分开考虑；切断舵机电源后机器人可能倒下，始终保持防坠条件。

采用 **阶段 0～8 的主线 + 阶段 9 的可选工程化**。软件与硬件并行，不必等整机装完才第一次接触 RL。

推荐并行关系：


不设置“几天必走”的承诺；每周按交付物推进，失败就停在当前层定位问题。

## 6. 各阶段任务与验收

### 阶段 0：硬件没到，也能先开始

**任务**：准备 Git、uv、Python 环境与训练电脑；下载手册、官方通讯示例、机械 CAD、训练仓库；建立自己的版本分支。用现有参考执行器配置跑小规模仿真，学习关节、观测、奖励和导出流程。

**资料记录**：舵机手册文件、官方例程来源、Git commit、CAD release、操作系统、驱动版本、GPU 显存、软件锁文件。

**验收**：

- [ ] Python、MuJoCo 能导入，CUDA/Warp 识别预期 GPU。
- [ ] 能列出 Microduck 任务，完成少量环境/少量迭代的冒烟测试。
- [ ] 明确当前运行的是哪种执行器配置。
- [ ] 保存日志，没有 NaN、模型缺失或依赖错误。

此阶段不需要舵机、IMU、ROS 或自制 PCB；在参考模型里学会走，只说明训练链路通了。

### 阶段 1：一个 S288，先安全地动起来

**任务**：固定舵机；断电核对线序与极性；准备可立即切断的舵机电源；用官方助手确认 ID、固件、故障、电压与位置。参照官方安全起步方式建立初始反馈，再从当前位置附近做小幅、缓慢运动。

**特别要求**：不要一上电就发“绝对位置 0”；不要在未确认含义时把“锁定模式”当成卸力，也不要把全零命令当成无害查询。S288 通常需要收到命令才返回反馈，具体安全初始化以官方例程和固件说明为准。[U1](#source-u1)

**验收**：

- [ ] 控制方向、位置单位和反馈字段核对正确。
- [ ] 记录至少一组目标/实际角度曲线。
- [ ] 受控环境验证停止、断连与超时行为。
- [ ] 无异常发热、异味、线束温升和故障码。

### 阶段 2：Pi 5 驱动和五节点通信

**任务**：在 Pi 5 上识别官方 USB 板，验证 6 Mbps；优先移植官方示例，再封装发送、收包、校验、超时、错误码与关节单位转换。逐台设置唯一 ID，避免出厂同地址设备一起接入。

采用单调时钟和绝对周期计划，例如每 20ms 更新一次目标。**每轮计算完再固定 sleep(20ms) 会把计算时间叠加到周期中**，不能当作准确 50 Hz 调度。

**建议验收目标（项目目标，不是厂家指标）**：

- [ ] 1 个、5 个分别完成持续日志测试，例如至少 10 分钟。
- [ ] 统计读写耗时、周期 P50/P95/P99、最大值、丢包与校验失败数量。
- [ ] 超期/丢包不会导致数组错位或把错误反馈当成有效角度。
- [ ] 20ms 周期有稳定余量；理想目标是读写与处理 P99 小于 15ms，达不到时先定位，不硬上机。
- [ ] 人为停止程序后，既能触发软件保护，也有独立的舵机断电手段。

这里只是项目性能目标，Pi 5 + USB + Python 不因此变成硬实时系统。

### 阶段 3：IMU 读数变成机器人状态

**任务**：LSM6DSV16X 模块直接接主控，优先选择已有可靠驱动的接口；SPI 是候选，不为了“更快”否定已经满足需求的 I²C。先读取原始加速度、角速度，再完成 SFLP 或主控姿态估计。

建立清晰的安装变换：传感器坐标 → 躯干坐标。确认前倾、后倾、左右翻滚和偏航的符号。四元数顺序、旋转方向、角速度单位均写入文档。

**验收**：

- [ ] 静止时角速度接近校准后的零偏，姿态没有明显跳变。
- [ ] 逐轴转动，读数与实际方向一致。
- [ ] 重力方向与训练坐标约定一致；参考 runtime 的直立重力为 `[0,0,-1]`。[S7](#source-s7)
- [ ] 数据附采样/接收时间及有效标志；不能“读到了数据”就忽略它已经过期。
- [ ] IMU 故障或姿态未初始化时禁止策略接管。

IMU 和舵机放进同一个数据包，并不证明它们在同一时刻采样。后续 MCU 方案也要处理时间差。

### 阶段 4：改 CAD，做一条腿

**任务**：以 XL330 版 SolidWorks 文件作机械起点，复制一份 S288 工作目录，保留原包不覆盖。插入准确的 S288 模型或基于图纸/实物制作的外形模型，核对孔位、输出盘、后端支撑、出线与关节行程。

优先顺序：安装孔试片 → 一个关节连接件 → 髋部连接 → 大腿/小腿 → 踝脚 → 一整条腿。尽可能保留参考设计的关节轴线和中心距，减少仿真修改量，但不以此牺牲装配与强度。机械源文件与版本入口见 [S11](#source-s11)。

**验收**：

- [ ] 模型与实物试装一致，螺丝不过深，不靠强行挤压安装。
- [ ] 五个关节的方向、零位和机械极限形成表格。
- [ ] 按限定范围缓慢联动无硬干涉，线束不拉紧、不夹线。
- [ ] 单腿固定测试下通信与供电稳定。
- [ ] 记录打印件、舵机、紧固件实际质量，并更新 CAD。

单腿可以验证机械和控制链，但**不能单独证明整机平衡、行走或全部热负载能力**。

### 阶段 5：S288 执行器辨识

**任务**：先用一个舵机搭小型台架，测不同小幅轨迹、方向、增益和已知负载下的响应，记录原始数据。先建立简单模型，再按验证误差决定是否引入 BAM 的扩展摩擦模型。

**验收**：

- [ ] 数据包含命令、实际角度/速度、状态、时间戳和实验条件。
- [ ] 训练集与验证集按完整实验分开，不随机拆相邻采样点。
- [ ] 同一模型在至少一种未参与拟合的负载/轨迹上进行验证。
- [ ] 同时检查短时重置误差和完整轨迹自由回放误差。
- [ ] 在其他 S288 个体上抽验，记录差异而不是宣称一套参数适合全部。

详细实施见第 8 节。此阶段不要求把电机内部 FOC 从头模拟一遍。

### 阶段 6：整机补齐、标定与配置冻结

**任务**：采购剩余舵机，装配整机，完成全部 ID、关节方向、零位与安全范围。验证 15 节点周期、供电分支、故障处理。确定最终主控、电池、安装位置与线束重量。

**务必在最终训练前确认**：Pi 5 是真实背在机器人上，还是仅作台架主控；最终是否改用 ZERO 3W；电池是否为 1800mAh 候选。重大质量/重心改变后，需要更新仿真，不能直接沿用旧结果。

**验收**：

- [ ] 15 个地址唯一，嘴部与 14 维策略动作映射明确。
- [ ] 受支撑状态下可从允许的姿态缓慢进入安全站姿。
- [ ] 记录整机质量、各刚体质量、质心、惯量、关节轴与限位。
- [ ] 主控在舵机负载变化时不欠压重启，连接器与线束无异常。
- [ ] 电池容量、保护阈值和每条供电路径有依据。

### 阶段 7：训练真正对应 S288 的策略

**任务**：用阶段 5、6 的结果替换仿真执行器与机械参数。保持第一版动作为 14 个关节位置目标，固定且经过验证的 Kp/Kd，先只训练基础平地行走。

检查训练、CPU 回放和板端使用的控制模式、零位、增益、延迟、限幅和观测顺序是否一致。域随机化范围由实测差异与合理不确定性给出，不随意把范围扩大当成万能修复。

**验收**：

- [ ] 仿真不是旧 HD1910/XL330 模型改了名字。
- [ ] 不同速度命令、轻扰动和至少多个初始化条件下回放正常。
- [ ] 无依赖穿模、超出实机限位或不合理扭矩的动作。
- [ ] 导出 ONNX 后再次回放，确认归一化、输入输出形状与数值有效。
- [ ] 模型、配置、CAD 版本、执行器参数与日志一起归档。

### 阶段 8：从不执行动作到安全行走

**任务顺序**：

1. **影子模式**：读取真实状态、运行 ONNX，但不下发动作，检查观测与目标范围。
2. **受支撑的小动作检查**：验证实际方向与位置映射；不把悬空时策略产生的行为当成落地能力。
3. **受保护站立**：地面有支撑，防坠装置不妨碍正常小范围运动。
4. **原地/低速行走**：逐步增加命令，保留人员可达的独立断电措施。
5. **重复与持续测试**：记录温度、故障、跟踪误差、周期及电池端功率。

首次动作检查可以限制幅度，但最终评估必须使用与训练匹配的控制配置；随意降低 Kp/Kd 后摔倒，不能直接说明策略不好。

**验收**：

- [ ] 无效/过期 IMU、舵机掉线、NaN、超限动作都能被拦截。
- [ ] 断连不会无限维持危险目标；受控停机与紧急断电分别测试。
- [ ] 同一任务能重复完成，注明地面、速度、时长和电池状态。
- [ ] 记录电池端 Wh，再讨论续航，不能照搬官方原机“一小时”。

### 阶段 9：可选升级，不与第一版同时展开

当外置线束、体积、时序或安全管理已形成明确瓶颈，再用 MCU 汇聚 IMU 与舵机总线，随后集成 PCB。小型化也可先只换主控与线束，不一定要一次完成自制板。

验收是“相同工况下回归通过”，不是“PCB 能上电”。主控或板卡位置、质量与延迟改变后，重新检查仿真配置和实机策略。

## 7. S288 驱动与关节数据约定

### 7.1 已知协议边界

根据用户上传的 J288/S288 手册：[U1](#source-u1)

| 项目 | 资料值/说明 |
|---|---|
| 物理通信 | 单线半双工串行通信 |
| 波特率 | 固定 6 Mbps，8N1 |
| 普通设备地址 | 0～14，共 15 个 |
| 广播地址 | 15；不能当第 16 个普通设备地址 |
| 命令/反馈长度 | 20 字节 / 26 字节 |
| 控制量 | 转子侧力矩前馈、位置、速度、刚度、阻尼 |
| 位置反馈 | 转子侧位置与独立输出端位置字段 |
| 减速比 | 288.35:1 |
| 超时保护 | 控制位可使能，手册标默认 1s；不是适合本项目的唯一安全保障 |

**实现要求**：按字节显式打包，不直接依赖编译器位域布局；CRC 使用官方算法和校验范围。发送、接收包对帧头的 CRC 处理不同，反馈结构体中还注明了不在线上传输的对齐字节，必须对照例程测试。

### 7.2 上层统一使用关节单位

上层使用 `rad、rad/s、N·m`，把转子侧协议细节封装到驱动。

设 `N=288.35`，在理想刚性传动、零位和方向已标定的条件下：

```text
转子位置差 ≈ N × 关节位置差
转子速度   ≈ N × 关节速度
理想输出力矩 ≈ N × 转子力矩
```

实际力矩还受效率、摩擦和控制标定影响；舵机上报的转子力矩不能未经校准就当成独立输出轴力矩传感器读数。

**Kp/Kd 也不是原数复制。** 若忽略传动损失，转子侧 PD 与输出侧 PD 的等效增益存在约 `N²` 的尺度关系。必须根据选定的控制侧、单位和官方例程推导并低风险验证；不要把 HD1910 的寄存器增益直接填进 S288 命令。

输出编码器与转子编码器的差值只有在零位对齐、方向一致、角度展开和采样时刻处理后才有意义；不能把差值全部解释为齿隙。

下表是本项目建议，**不是宇树出厂约定，也不是必须照抄的官方 Microduck ID**。只要驱动、标定和训练映射一致即可。

| S288 ID | 关节名 | 14 维策略索引 |
|---:|---|---:|
| 0 | left_hip_yaw | 0 |
| 1 | left_hip_roll | 1 |
| 2 | left_hip_pitch | 2 |
| 3 | left_knee | 3 |
| 4 | left_ankle | 4 |
| 5 | neck_pitch | 5 |
| 6 | head_pitch | 6 |
| 7 | head_yaw | 7 |
| 8 | head_roll | 8 |
| 9 | right_hip_yaw | 9 |
| 10 | right_hip_roll | 10 |
| 11 | right_hip_pitch | 11 |
| 12 | right_knee | 12 |
| 13 | right_ankle | 13 |
| 14 | mouth | 不进入该 14 维行走策略 |

为每个关节保存：ID、方向、输出零位、转子/输出端对应关系、机械限位、软件安全限位、站姿目标、增益和固件版本。上电后转子多圈计数的重置行为必须纳入初始化，不只做一次标定就永远假定有效。[U1](#source-u1)

### 7.4 周期与安全

15 台各一次 20+26 字节通信，8N1 计 10bit/字节，纯线路时间下限为：

```text
15 × (20 + 26) × 10 / 6,000,000 ≈ 1.15ms
```

这是根据协议长度计算的理想线速下限，**不含逐台应答间隔、USB 缓冲、操作系统调度和重试**，不是实测采样周期。[U1](#source-u1)

建议日志字段：

```text
t_command / t_receive / sequence
servo_id / valid / crc_ok / error_code
q_target_joint / q_joint / dq_joint
rotor_position / output_position / rotor_velocity
reported_rotor_torque / supply_voltage / temperature
imu_timestamp / gyro_body / gravity_body / quaternion
loop_duration / deadline_miss / safe_state
```

安全策略至少包括：启动禁止、人工使能、有效数据检查、关节限位、目标变化率约束、温度/电压/错误处理、通信超时和独立断电。阈值由实测与器件限制确定，不在没有验证时发一套“通用 Kp/Kd”。

## 8. BAM 建模实施路线

### 8.1 先明确要做的是什么

BAM 是 **Better Actuator Models**，提供执行器建模、扩展摩擦、数据采集和参数拟合的方法。它不是用 PPO 训练出来的步态网络，也不是 S288 的新固件。[S6](#source-s6)

**不要求一开始就完成复杂 M6 模型。** 建议从可解释的简单模型开始：

```text
位置目标 + 固定、已验证的 Kp/Kd
      ↓
与实机一致的控制规律
      ↓
力矩限制 / 响应延迟 / 等效惯量
      ↓
简单摩擦
      ↓
单关节动力学
```

只有简单模型在独立验证中暴露出明确问题，再加入低速摩擦、负载相关摩擦、方向性、齿隙或速度相关力矩边界。S288 的混合控制可以作为模型结构起点，但不能假设它在所有工况下是理想力矩源。[U1](#source-u1)[S6](#source-s6)

### 8.2 台架与数据

一个固定 S288、已知几何的摆臂和小配重即可开始。初期先轻载、小角度、低速度，不照搬其他舵机的最大幅度轨迹或自由落体实验。

记录摆臂质量、质心、端部配重、有效力臂和惯量。摆动时负载不仅有重力，还包含加速惯性；`m×g×L` 只是特定姿态的静态量，不是全部动态载荷。

推荐实验顺序：

1. 空载/轻载的小幅平滑往复，检查方向和延迟。
2. 低速往返，观察死区、停滞和反向差异。
3. 小幅多频或渐变频率轨迹，观察响应带宽。
4. 改变已知负载与安全增益，覆盖计划使用的工作区间。
5. 其他舵机个体复测，估计一致性。

原始采样频率以能稳定获取的新数据为准。可争取数百 Hz 的台架记录，但不能把 50 Hz 原始数据插值成 200 Hz 就当作新增了真实信息。命令重采样应匹配实际保持/插值方式，不能无意改变输入波形。[S6](#source-s6)

### 8.3 软件适配不只是换文件名

BAM 的现有 `UnitreeGo1Actuator` 可以作为控制模型组织方式的参考，**不是 S288 已被支持的证明**。新执行器需完成注册、控制规律、单位、限制、日志解析和测试。

完整接入需要分别验证：

| 层 | 必须处理 |
|---|---|
| 硬件采集 | S288 驱动与安全采集程序 |
| 离线模型 | S288 控制律、参数范围、拟合与回放 |
| 执行器注册 | 工具能识别 `s288`；命令行支持该名字 |
| GPU 训练 | 所用 BAM/MjLab 版本是否支持该自定义类，否则需要实现对应张量/Warp 路径 |
| CPU ONNX 回放 | 使用同一 S288 模型，不能仍然加载默认 XL330/HD1910 |
| 实机部署 | 相同控制模式、增益、限位和时间约定 |

因此，**仅新建 `s288/m5.json` 或把 `motor_name="hd1910"` 改成 `"s288"` 并不代表适配完成**。[S5](#source-s5)[S6](#source-s6)

### 8.4 拟合、验证与产物

先拟合少量可辨识参数，再比较更复杂模型。BAM 文档提供 M1～M6、MAE 目标及验证集机制；应根据验证误差选择，不默认 M6 最好。[S6](#source-s6)

数据按完整轨迹/负载/重复实验划分，保存一部分从未参与拟合的记录。不要只报告频繁重置仿真状态后的漂亮误差；同时检查完整轨迹、延迟、超调和负载变化。

应交付：

```text
S288 参数文件
+ S288 模型实现
+ 台架与电源条件说明
+ 采集程序
+ 原始数据与处理方式
+ 拟合/验证分组
+ 真实与仿真对比报告
+ 软件版本/参数版本
```

通信延迟可能随主控、USB 板、节点数量和固件改变。单舵机台架的延迟不能直接当成 15 舵机整机延迟。

## 9. RL 环境入门与部署

### 9.1 电脑端和机器人端分开

| 平台 | 当前任务 |
|---|---|
| NVIDIA GPU 电脑 + Ubuntu | 训练与 GPU 仿真首选 |
| Windows + WSL2 + NVIDIA GPU | 可作为候选；先验证驱动、CUDA/Warp 与图形回放，不等于全部依赖已被项目逐项认证 |
| macOS / 无 NVIDIA GPU 电脑 | 看代码、处理数据和可用的 CPU 仿真；本项目 CUDA 训练使用其他 GPU 主机 |
| Pi 5 / ZERO 3W | 读取硬件与运行导出的策略，不承担这条 CUDA 训练流水线 |

WSL 的 CUDA 支持由 Windows 驱动配合提供；不要把原生 Ubuntu 的驱动安装命令不加区分地执行到 WSL 中。[S9](#source-s9)

BAM 离线参数拟合与大规模 PPO 训练不是同一件事。很多离线拟合可使用 CPU；没有 GPU 不妨碍先做驱动、CAD 和台架记录。[S6](#source-s6)

### 9.2 软件采购清单：多数不是新硬件开销

| 软件 | 是否现在需要 | 用途 |
|---|---|---|
| Git、uv、Python | 是 | 代码与隔离依赖管理 |
| MuJoCo、MjLab、Warp、PyTorch | 训练阶段 | 由项目依赖管理，别混装进系统 Python |
| ONNX Runtime | 部署阶段 | CPU 策略推理 |
| 宇树调试助手与官方通讯例程 | 舵机到货后 | 建立已知可用的硬件基线 |
| SolidWorks | 机械阶段 | 使用现有合法可用版本；先检查源文件兼容性 |
| 切片软件 | 打印前 | 生成适合实际打印机的文件 |
| ROS / Isaac Sim / Isaac Lab | **本路线不要求** | 不作为起步阻塞项 |
| 云 GPU | 可选 | 本地资源不足时再评估费用，不提前长期租用 |

### 9.3 首次环境建立示例

下面是 **Ubuntu 或 WSL2 中的项目环境示例**，不涉及驱动舵机。安装 NVIDIA 驱动应按自己的系统单独完成；先让 `nvidia-smi` 正常，再往下进行。

```bash

sudo apt update
sudo apt install -y git curl build-essential

# 2. uv；来源为 Astral 官方安装文档
curl -LsSf https://astral.sh/uv/install.sh | sh
# 安装后重新打开终端；默认安装目录可按如下加入当前 PATH
export PATH="$HOME/.local/bin:$PATH"
uv --version

# 3. 训练参考仓库：保留它是参考模型，不是现成 S288 方案
mkdir -p ~/projects
cd ~/projects
git clone --branch develop https://github.com/JoyandAI/microduck_rl.git
cd microduck_rl

git switch -c s288-port
uv python install 3.12
export UV_HTTP_TIMEOUT=600
uv sync --locked

# 4. 记录环境；保留仓库自带的锁文件
mkdir -p local_notes
git rev-parse HEAD > local_notes/base_commit.txt
uv run python --version

# 5. 分别检查计算库，不以“安装没有报错”代替检查
uv run python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
uv run python -c "import mujoco; print(mujoco.__version__)"

# 6. 列任务与查看当前 CLI
uv run list-envs
```

当前查阅的 JoyandAI 配置要求 Python `>=3.12,<3.13`，并锁定了 MjLab/PyTorch 等依赖；后续以自己冻结的 commit 与 `uv.lock` 为准。若 `--locked` 报锁文件不一致，先查原因，不直接删锁文件重新随机解析。[S4](#source-s4)[S10](#source-s10)

第一次采用少量环境，例如 64 个、5 次迭代作冒烟测试；参数名以本地 `--help` 为准。显存较小时从小规模开始，**不要直接复制 4096 环境并把显存不足理解成电脑完全不能训练**。

### 9.4 哪些现成东西可以复用

可复用训练框架、PPO、任务组织、日志、导出思路和参考观测结构；需要核对或改造的是机械动力学、S288 执行器、读写驱动、增益与零位。

当前读取的 JoyandAI 配置仍明确使用 `motor_name="hd1910"`、`model="m5"`、`kp_fw=32` 及其电压/延迟设置。**这些数值不属于 S288。**[S5](#source-s5)

第一版策略建议仍输出 14 个位置目标：

```text
状态观测 → 策略 → 14 维 action
                    ↓
         按训练配置映射为关节目标
                    ↓
         零位 / 增益 / 限幅 / 安全层
                    ↓
                 S288 驱动
```

不在第一版同时让网络学习目标位置、Kp、Kd、速度和前馈力矩。先固定经过验证的底层配置，减少变量。

### 9.5 导出、回放与部署交付包

参考仓库提供的流程是 checkpoint → 项目 exporter → ONNX → CPU MuJoCo 回放。[S4](#source-s4)

```bash

uv run scripts/export.py --help
uv run scripts/infer_policy.py --help

# 使用参考仓库文档中的 W&B 路径导出方式时：

RUN="your_entity/your_project/your_run_id"
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck --wandb-run-path "$RUN"

# 输出路径以 exporter 实际提示为准
# 回放前必须核对回放端已切到相同的 S288 模型
uv run scripts/infer_policy.py --walking output.onnx
```

S288 部署包建议包含：


文件名是本项目建议，不代表上游已有这些文件。ONNX 中是否包含观测归一化、是否有历史观测/额外输入，以实际 exporter 和模型元数据为准，部署前逐项验证；不能重复归一化或漏掉归一化。

## 10. 后期自制下位机

### 10.1 目标架构

```text
Pi 5 / ZERO 3W
  ONNX策略、任务命令、日志
          │
          │ USB / UART：目标与带时间戳状态
          ▼
自制 STM32 汇聚控制板
  ├─ SPI → LSM6DSV16X
  ├─ 6 Mbps 半双工 → S288 ×15
  ├─ 电池电压 / 电流监测
  ├─ 主机超时 / 舵机故障处理
  └─ 舵机使能 / 独立断电接口
```

此时确实是上下位机。S288 自己内部仍负责电机控制，不需要 STM32 重新写整套 FOC。[U1](#source-u1)

### 10.2 不把 IMU 伪装成第 16 个 S288

普通 S288 地址 0～14 已被 15 个舵机占满。自制板作为**总线主机与 IMU 汇聚器**，由它读取 IMU 后通过另一条主机链路上报；不用抢广播地址，也不把现成 `imu_to_dxl` 直接移植到同一条 S288 总线上。[U1](#source-u1)[S7](#source-s7)

### 10.3 先开发板，再 PCB

先验证：实际 UART 时钟能产生可靠 6 Mbps、收发换向时序、USB/UART 吞吐、DMA 缓冲、IMU 初始化、主机协议与断连策略。然后再画电源和接口集成板。

候选频率可从策略 50 Hz、总线管理 100～200 Hz、IMU 较高输出频率进行评估，但这些只是预算起点，不是已验证指标。状态组包不等于同步采样；需要统一时钟或时钟映射，记录各数据年龄。

**关键安全逻辑：**若 Pi 失联，下位机不能永远重发最后一条目标来“维持通信”，否则会掩盖上位机故障，甚至使舵机自带超时保护永不触发。下位机必须单独检测命令新鲜度并执行已验证的安全动作。

### 10.4 PCB 设计检查项

| 部分 | 设计前必须有的数据 |
|---|---|
| 3S 输入 | 电池范围、峰值电流、接头、反接和短路保护要求 |
| 舵机馈电 | 分支电流、连接器额定值、允许压降与铜箔温升 |
| 回灌/浪涌 | 实测波形与能量；不能随便放一个 TVS 就宣称解决 |
| 主控降压 | 实测功耗、启动峰值、USB-C 供电约定与热条件 |
| 通信收发 | 官方电平/电路建议、换向时间、波形与布线长度 |
| IMU | 安装轴向、供电噪声、机械固定、驱动支持 |
| 安全 | 急停、看门狗、欠压、故障上报、主控正常关机策略 |
| 维护 | SWD、测试点、固件升级、丝印和防插错 |

不要用“后期肯定要自制板”倒推第一版必须先画板。只有当集成需求与测量数据足够明确，画板才更容易一次成功。

## 11. 风险清单与执行看板

### 11.1 最容易造成返工的事项

| 风险 | 避免方式 |
|---|---|
| 15 地址误当成 15 舵机供电认证 | 索取转接板、连接器与线束额定值，测实际电流与温升 |

| 认为 STEP 等于原始特征树 | STEP 一般是交换几何；需要草图/特征时优先原生 SW，实际打开检查 |

| 默认 S288 无刷一定更省电/更耗电 | 在相同任务下测电池端能量，不用不同厂家空载数据推整机倍数 |

| 用默认一秒超时替代全部保护 | 主机和下位机独立检测时效，增加可达的舵机断电 |
| 用 5 个舵机测试结果承诺整机行走 | 五节点只是局部验证，15 节点、整机受力与热必须另测 |

## 最终执行原则

**先用现有主控和电池，把 1 个 S288 变成可测、可控、可安全停下的执行器；再做五节点和一条腿；用实测数据指导机械、供电与仿真；最后才补齐整机、训练并部署。**

自制板、更多外设和复杂动作，都建立在前一层已经验证的基础上。
